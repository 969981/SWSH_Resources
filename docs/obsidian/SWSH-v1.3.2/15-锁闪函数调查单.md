# 锁闪、PID、IV 实时生成：证据调查单

目标：判断野外、固定、礼物、交换、巢穴与配信是否存在不同的闪光判定或重掷路径。

第一步：静态核对 `ShinyLock` 来源、类型和实际数值；对应 `EncounterStaticArchive`、`GiftArchive`、`EncounterTradeArchive` 和活动团体战 schema。第二步：构造不同锁闪/保底 IV 的对照场景，在本机隔离环境中记录生成前的 Encounter 配置与生成后的 PID、TID/SID、IV、是否闪光。第三步：从赋值点寻找读取路径、调用栈和 `main+RVA`；固定并记录游戏版本与 main SHA256；对比剑盾两个 main。

记录模板：`build_id,sha256,module_base,main_rva,instruction,registers,source_struct,field_value,pid,iv,observed_shiny,proof,status`。目前仓库未提供经独立验证的完整地址列表，不写虚构 RVA。
