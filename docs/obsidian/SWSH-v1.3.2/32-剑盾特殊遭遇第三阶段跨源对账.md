# SWSH v1.3.2：特殊遭遇第三阶段——源表与 PKHeX 模板对账

关联：[[31-剑盾巢穴配信与固定遭遇PKL补全]]、[[18-巢穴结构字段表]]、[[25-天气渗透268例运行时验证]]。

## 证据锚点

- 原始游戏版本：Sword / Shield 1.3.2。绝不修改源二进制、原始 inventory。
- PKHeX 固定源码：`kwsch/PKHeX@0660d1e1f4924b8478daec73281bb8071a82ad19` 的 `PKHeX.Core/Legality/Encounters/Data/Gen8/Encounters8.cs`；Git Blob SHA-1 `b01b60a9d35fb865f3191b923dcec65935cd74ea`。
- 原版 CSV 的 blob SHA 及原始二进制 SHA-256 均写在各自的 `manifests/swsh_*_pkhex_v132.json` 中；检测时会重新读取原始源文件验算。
- 这些数字是 **静态源与当前所固定 PKHeX C# 数据快照** 的对账，不代表历代活动包完整覆盖。

## NPC 交换：23 条 ROM 行 → 22 个 PKHeX 交换模板

`manifests/swsh_trade_pkhex_v132.json` 保留所有行的 C# 源码行号、版本限制和 12 字段 JOIN。

| 验证项 | 结果 |
| --- | ---: |
| ROM `field_trade.bin` 导出行 | 23 |
| PKHeX `TradeSWSH` | 14 |
| PKHeX `TradeSW` / `TradeSH` | 4 / 4 |
| 12 字段唯一匹配的 ROM 行 | **23 / 23** |
| 找不到对应 ROM 行的参考模板 | **0 / 22** |
| 有意保留的多对一 | **双弹瓦斯源行 8、9 → `TradeSWSH:780`** |

12 个 JOIN 字段：物种、形态、等级、ID32、记忆 ID、记忆变量、心情、强度、极巨化等级、OT 性别、第一再学习招式和原始锁闪枚举。这些特征可以在目前固定数据上确定映射，而不是靠物种名字猜测。

注意：两条双弹瓦斯记录的原始 AbilityNumber 为 0 和 3，参考模板标注 `Any12H`。多对一不是让人删除原始行；**原版 AbilityNumber 和 PKHeX AbilityPermission 的完整运行时编码语义仍待单独证明**。原始交换表不直接证明剑/盾版本区分，`SW`/`SH` 是对 PKHeX C# 模板版本字段的引用。

**评级：** `STRUCTURAL_12_FIELD_MATCH_NOT_RUNTIME_PROVEN`，不等于 NPC 在当前剧情下可触发，不等于 100% 合法宝可梦构造器。

## 剧情赠送：31/31 单一候选

同一 C# 快照解析出静态模板共 676 条：`StaticSWSH=627`、`StaticSW=25`、`StaticSH=24`。原版 `add_poke.bin` 的 31 条记录，在当前保守 JOIN 下均有一个候选模板。

仅比较物种、形态、等级；如果 C# **显式**指定招式或 `CanGigantamax=true`，再进行相应过滤。没有将 `FixedBall`、原始 `IsEgg`、`ShinyLock`、无标记规则等尚未证明相等的语义强行视作同值。

这只是单一候选（`SINGLE_CANDIDATE`），**不是** 31 条游戏内赠送都已完成剧情触发测试。

## 固定遭遇：647 条原始行

| 静态关联类别 | 原始行数 | 能作出的结论 |
| --- | ---: | --- |
| 单一候选 | **476** | 当前保守条件仅产生一条 PKHeX 静态候选 |
| 多个候选 | **126** | 不能在无脚本状态/地图关联证据下判定唯一来源 |
| 无候选 | **45** | 该 C# 快照和筛选规则未匹配，不表示游戏内非法或原始表有错误 |
| 合计 | **647** | 源文件所有行都被保留并分类 |

部分原版记录可能指向同一个 PKHeX 合法性模板（例如不同剧情阶段的反复登场），所以即使对一条源行只有一个候选，也不能推导所有关系为 1:1。

**45 条无候选的第一层排查：** 其中 44 条不存在相同物种＋形态＋等级的静态 PKHeX 模板；1 条是原始第 23 行（盾兽 / Zamazenta，物种 889，等级 70），具有同物种等级候选但与 C# 显式指定招式不一致。它们包括剧情战斗及中间生成模板，不能据此断言原始表错误或存在 45 条应当被捕获的遗漏。

`scripts/audit_swsh_static_gift_pkhex.py` 会输出 `gap_reason` 和 `no_candidate_reason_histogram`，保留逐源 `source_row`；这里描述的是候选筛选失败阶段，**不是游戏合法性失败原因**。

`manifests/swsh_static_gift_pkhex_v132.json` 固定 676 条参考模板及当前覆盖分布；`scripts/audit_swsh_static_gift_pkhex.py` 导出逐行候选模板 ID、源码行号对应关系（经参考清单查询）、`NO_CANDIDATE`/`SINGLE_CANDIDATE`/`AMBIGUOUS_CANDIDATES`。**原始 EncounterScenario 不是 PKHeX 捕获地点 Location。**

## 普通巢穴：加强差异归因入口

`scripts/audit_swsh_raw_nests.py` 新增：

- 未匹配源候选逐条绑定 `table_id`、`entry_index`、`level_table_id`、`drop_table_id`、`bonus_table_id`、五档原始权重与源 SHA-256；
- `potential_nest_reindex_overlap`：忽略 Nest index 后两端未匹配集合可能出现的重合；
- `potential_rank_span_overlap`：忽略等级范围后的可能重合；
- `potential_ability_gender_overlap`：忽略特性与性别后的可能重合。

后三种数字属于**彼此可以重叠的诊断候选**，不是已证明的原因，更不能相加得出已修复数。需要结合原生散列 JOIN、pkNX/PKHeX 整理规则与游戏运行时记录做下一轮判别。
